# 链路监控产品需求说明书

版本：PRD V1.4，2026-09-17。状态：P01 当前指标与 P04 指标趋势增量稿（文件名沿用 V1.0）。本次仅改总览与链路详情，其他页面保留原内容。

依据：[链路监控需求基线 V1.6](./链路监控_需求基线_V1.md)，指标相关内容以第17章最新规则为准。适用对象：产品、设计、研发、测试及内部维护人员。

本文将已确认基线转化为页面、流程和可执行规则。基线规则标为 B，基于基线补齐的 UI、UE 及流程细节标为 D；D 是本稿的设计方案，不代表用户已经逐条确认。实施参数标为 P，见第 12 章。基线不因本稿自动变更。

## 1. 产品目标与范围

统一展示电网业务的逻辑拓扑，使用户能按业务定位完整链路、识别异常或未知对象、查看最近 30×24 小时状态，并以共享资源方式维护多条业务链路。

一期包含：业务查询和拓扑聚焦，Node/Edge 管理及复用，Path 草稿编排、校验、确认发布和单条启停，人工 Role，多层当前状态与区间历史，逐条引用替换、资源停用与受限删除，模板导入及操作日志。权限接入现有体系。

一期排除：业务对象整体状态和整体启停、批量迁移、主备/双活/替代 Path、实例展开、历史拓扑恢复、自动发现、人工执行步骤、Span 精确播放、业务埋点改造、具体畅通算法和告警联动。

### 1.1 典型业务场景

- 广电一区和三区指令链路共用前段服务、在尾端处理分化：总览只画一次公共对象，选择任一 Path 时突出其完整组成。
- 同一业务对象包含上行、下行两个 Path：查询该业务可同时聚焦两条链路，分别查看状态和执行启停。
- 共享接入服务调整：新建替代逻辑资源，在指定 Path 草稿中替换引用，发布后该 Path 使用新组成，其他 Path 继续使用旧资源。
- 运维查看昨日下午异常：查看 Path 已保存的历史状态及当前拓扑下可关联对象的历史，不恢复昨天的结构。

## 2. 业务模型与数据含义

### 2.1 对象及关系 B

| 对象 | 业务含义 | 关系及边界 |
| --- | --- | --- |
| 业务对象 | 用于将相关上下行链路按业务查询、聚焦的归组信息 | 每方向最多一个 Path，允许单方向；无整体状态和启停 |
| Path | 一个具体业务方向及目标的完整静态拓扑 | 包含多个 Node、Edge；串行、分支、汇聚和反向交互均可表达 |
| Node | 平台、应用服务、中间件/组件或设备等逻辑资源 | 多 Path 复用；一期不展示部署实例 |
| Edge | 两个 Node 之间有方向、业务作用的信息流转关系 | 多 Path 可复用；同一对 Node 可有不同业务 Edge |
| PathNode | Path 引用 Node 的关系 | 同一 Path/Node 唯一；保存多个 Role |
| PathEdge | Path 引用 Edge 的关系 | 同一 Path/Edge 去重；Edge 两端属于该 Path |
| Role | Node 在特定 Path 内承担的功能 | 人工从受控字典多选；不写为 Node 全局角色 |
| Span | 一次实际业务执行中的运行时记录 | 根据真实父子标识关联；不强制绑定 Edge，不由人工编排 |
| 状态区间 | 对象某状态持续的起止记录 | Node、Edge、Path 三层，滚动 30×24 小时 |

拓扑组成与真实执行次数独立。同一 Node 或 Edge 被多次经过不重复创建静态对象；图上箭头表示 Edge 通信方向，不能据此推导执行先后。

### 2.2 逻辑字段设计 D

以下为产品语义字段，接口命名与现有资源系统映射在实施阶段确定。

| 对象 | 字段 | 输入及校验 |
| --- | --- | --- |
| 业务归组 | 业务对象编码、名称、业务目标、业务范围 | 编码稳定；同编码的目标/范围不一致时提示冲突，禁止直接归组 |
| Path | 系统标识、名称、具体业务目标、链路类型、业务方向、业务范围、可选归组、说明 | 标识生成后不随名称变化；名称/类型/目标/范围必填；方向按业务适用性填写 |
| Node | 系统标识、名称、类型、稳定资源标识、所属范围、说明、标签 | 名称/类型/范围必填；稳定资源标识优先匹配已有资源；缺失时人工辨认并记录结果 |
| Edge | 系统标识、源 Node、目标 Node、业务作用、故障影响范围、名称/说明/标签 | 两端、业务作用、故障影响范围必填；方向以源→目标确定，反转即语义变更 |
| PathNode | Path 标识、Node 标识、Role 集合 | 组合唯一；按字典定义验证必选及互斥，不自行编造互斥规则 |
| PathEdge | Path 标识、Edge 标识 | 组合唯一；不得引用缺失端点 |
| 发布信息 | 当前生效配置标识、发布时间、操作人、待发布草稿 | 用于识别生效配置和并发编辑，不提供 Node/Edge 多版本库或历史拓扑恢复 |
| 状态 | 对象类型/标识、基础或聚合状态、状态生效时间、最后有效更新时间、来源/原因 | Node/Edge 仅三态；Path 五态；管理状态单独保存 |
| 区间历史 | 对象标识、状态、开始时间、结束时间、来源 | 当前持续区间结束时间可为空；显示时裁剪到查询范围 |

文件链路等不适用上下行业务归组的场景仍可作为独立 Path 管理，不强行标为指令上行或下行。方向具体枚举见 P1。

### 2.3 唯一性与复用 B

Node 以稳定资源标识判同，名称/类型/区域仅辅助判断。跨区域资源若故障、维护和状态可独立发生，分别建立 Node。缺少稳定标识时人工确认，不自动合并。

Edge 复用须源、目标、方向、业务作用、故障影响范围五项一致。系统给出候选，由人工选“复用已有”或“新建独立关系”。五项相同但用户选择独立创建时仍保留不同 Edge 标识，后续不能因属性相同在画布上再次合并。

融合画布按已确认的对象标识去重，不按名称、坐标、线段外观去重。

## 3. 核心业务规则

### 3.1 归组 B

统一业务对象编码、业务目标、业务范围一致且方向互补时给出归组候选，人工确认。每方向最多一条，允许只有上行或只有下行。已有同方向 Path 时禁止发布重复归组，提示现有 Path 名称和入口。

归组在 Path 草稿中建立、修改或解除，确认发布后生效并记录日志。归组不产生新的整体运行状态，不支持整体启停。

### 3.2 配置与启停 B 及操作细节 D

| 情形 | 当前监控使用什么 | 可执行动作 |
| --- | --- | --- |
| 新建未发布草稿 | 不进入当前监控 | 保存、校验、确认发布 |
| 已发布，无修改草稿 | 当前生效配置 | 查看、编辑、单条启停 |
| 已发布且存在草稿 | 仍使用当前生效配置 | 继续编辑、保存、校验、确认发布；监控不使用草稿内容 |
| 已发布且停用 | 不新增 Path 聚合结果 | 查看详情/历史、编辑、启用；保留最后状态和时间 |

D：首次发布时明确选择发布后启用或停用，不通过默认值暗中启用。已有 Path 再发布保持当前启停状态。保存只保存草稿；发布确认后整体替换该 Path 的当前配置及关系。发布失败保留旧生效配置与草稿，不产生部分替换。

D：离开存在未保存修改的编辑页时提供“保存草稿后离开、放弃本次未保存修改、继续编辑”。放弃未保存修改不删除已保存草稿。

D：发布前比较生效配置标识及引用资源最新状态；若他人已修改或资源已不可引用，提示刷新并重新校验，禁止覆盖他人结果。无需额外审核人员，按钮权限由现有体系判定。

D：草稿保存也携带草稿修订号；两个用户同时编辑时，仅修订号仍匹配的一次保存成功，后提交者保留未提交内容并提示比较最新草稿，不自动覆盖。草稿资源创建一经成功保存不随离页自动删除；未使用资源只能按既定零引用、未发布及无有效历史关联条件处理。

### 3.3 共享资源修改 B

| 操作 | 规则 | 对其他 Path 的影响 |
| --- | --- | --- |
| 修改名称/说明/标签 | 受控修改，提交前显示引用影响范围，记录日志 | 同一共享对象展示属性同步变化；不改变语义 |
| 修改 Node 业务身份 | 创建新逻辑对象，在指定 Path 草稿替换引用 | 未替换的 Path 继续引用旧对象 |
| 修改 Edge 端点/方向/作用/影响范围 | 创建新 Edge，在指定 Path 草稿替换 | 不原地改写共享 Edge |
| 从 Path 移除 Edge | 草稿内解除 PathEdge | 其他引用和 Edge 本体保留 |
| 从 Path 移除 Node | 草稿内解除 PathNode | D：展示关联 Edge，确认后同时解除本 Path 内这些 Edge 的引用，不删除全局对象 |
| 逻辑停用 Node/Edge | 禁止新增引用；已有发布引用保留并标记待迁移 | 不自动停用 Path，不直接改运行状态 |
| 物理删除 | 未发布、零引用、无有效历史关联才可删除 | D：引用检查包含已保存草稿及发布关系；提交时重新校验 |

B：比较该 Path 当前生效与拟发布的 Node/Edge 引用集合。保留原停用资源引用时允许发布其他修改，提示待迁移；拟发布集合新增的停用资源引用禁止。中间删除再加回但最终集合不变，不算新增；已发布解除后再加回属于新增。首次发布无原引用豁免。允许保留原引用不豁免其他发布校验；不再显示待裁定提示。

D：资源状态不清晰时不展示“可删除”；说明未满足条件。历史关联及日志保留策略按 P5 接入现有约定，界面删除不能连带清除历史。

### 3.4 Role B

Role 完全人工维护，字典多选，同一 PathNode 多 Role 汇总。字典是否支持禁用、对已有引用和新增选择的影响按 P1 接入现有治理约定，未确认前不新设字典禁用流程。修改 Role 随 Path 草稿发布生效。

## 4. 状态与历史规则

### 4.1 基础状态输入 B

外部监控/探针提供 Node、Edge 的基础状态，本模块接收并聚合。无监控数据为未知。按对象类型配置有效期，当前时间超过最后有效更新时间加有效期则转未知，并展示“数据已过期”。具体采集指标和畅通算法由现有监控能力负责。

D：界面区分“未知·暂无数据”和“未知·数据过期”；加载失败显示读取失败提示，不能把请求失败写成对象异常。事件时间、接收时间、重复/乱序处理及多来源优先级需要接入契约 P3，不能自行将最后收到的报文等同最新有效状态。

### 4.2 Path 聚合 B

令 n 为当前 Path 中唯一 Node 和 Edge 总数，a 为异常数，u 为未知数，r 为正常数。

| 条件 | Path 状态 |
| --- | --- |
| r=n 且 n>0 | 正常 |
| a=n 且 n>0 | 异常 |
| u=n 且 n>0 | 未知 |
| 0<a<n | 部分异常 |
| a=0、0<u<n | 部分未知 |

D：空草稿不计算运行状态，显示“未发布”；禁止空拓扑发布，避免空集合误判全部正常。异常和未知混合优先显示部分异常。状态详情列出异常、未知对象，标注来源和更新时间。业务对象无聚合结果。

### 4.3 停用与重新启用 B/D

B：Path 停用后退出默认总览，停止生成新聚合结果，详情显示“已停用”和停用前最后状态/时间。Node/Edge 继续供其他 Path 使用，不随 Path 停用。

D：停用时关闭当前有效状态区间。启用时按当前配置及有效基础数据立即重新聚合，不沿用停用前状态；基础数据过期按未知处理。历史停用时段以“未生成状态”灰色间隔展示，不计为正常、异常或未知的持续时间。

### 4.4 区间历史 B/D

B：Node/Edge/Path 均保存滚动 30×24 小时状态区间，记录状态、开始、结束、来源，使用 Asia/Shanghai 展示时间。跨窗口持续的状态保留覆盖窗口的有效片段。

D：查询采用左闭右开时间区间；持续时长按状态区间与查询区间的交集计算。相同状态连续刷新更新最后有效时间，不凭每次刷新新增状态变化。当前区间暂未结束时，展示持续至查询结束或当前时间。

历史图固定提示“按当前拓扑展示”。Path 时间轴读取当时已保存的 Path 历史，不用今天的对象集合重算昨天结果。点选时间只给当前拓扑内存在且有对应历史的对象着色。当前新增对象在选定历史时间无记录时显示“无历史记录”，不伪造历史正常/未知；已经移出的对象不重绘。固定补充提示“当前图可能与当时组成不同，不能据此完整还原当时的异常原因”，不依赖不存在的历史拓扑检测接口。即使当前节点有历史，也不代表当时已参与该 Path。

D：仅因查询没有返回记录而出现的空白，区别于已保存的“未知”状态。不得将区间查询结果擅自汇总成一个新“时间段整体状态”；使用时间轴和区间列表。

## 5. 核心流程

### F01 创建并发布 Path

从链路管理新建 → 填写业务信息 → 选择已有 Node 或新建 → 添加有向 Edge 并确认复用 → 维护 Role → 归组候选确认 → 保存草稿 → 校验 → 查看发布摘要 → 确认发布。

发布摘要包含业务信息、Node/Edge 数量、归组结果、新增/移除引用、Role 变化、首次发布后的启停选择。成功后进入详情并显示生效时间；失败停留草稿并提供可定位原因。

### F02 按业务定位异常

总览选择业务对象 → 画布聚焦相关上/下行 Path → 分别查看 Path 状态 → 选中异常 Path → 查看异常/未知对象清单 → 点选对象定位画布并查看状态来源 → 必要时进入历史。

筛选与高亮不改变 Path 的聚合范围。不能因为隐藏正常节点或切换区域就重新计算一个局部 Path 状态。

### F03 逐条替换共享引用

查看旧资源引用列表 → 打开某一 Path 编辑 → 创建/选择新 Node → 为受影响连接选择/新建 Edge → 确认 Role → 解除旧引用 → 校验 → 确认发布。

单条 Path 发布成功前旧配置持续有效；其他 Path 不受影响。新对象不继承旧对象历史状态。无批量选择迁移按钮。只更换 Node 但未调整 Edge 端点时发布校验失败。

### F04 单条启停

链路管理/详情点击停用 → 显示“停止此链路的新状态聚合，保留配置和已有历史” → 确认 → 列表更新，默认总览移除该 Path 独占对象，共享对象继续显示。

重新启用 → 校验存在有效发布配置 → 基于当前基础状态生成结果 → 回到默认总览。D：请求超时先刷新真实状态再允许重试，不显示未经确认的成功结果。

### F05 资源停用及删除

资源详情查看引用 → 停用确认 → 禁止新引用、原引用待迁移 → 在各 Path 逐条替换。物理删除需系统检查全部条件；引用仍存在、曾发布或有历史关联时给出原因，保留停用流程。

### F06 初始化导入 D

下载模板 → 上传 → 预检查 → 显示错误行和复用候选 → 人工确认 → 创建草稿 → 逐条校验和发布。

建议模板分业务/Path、Node、Edge、PathNode Role、PathEdge 引用表；使用稳定编码交叉关联。上传不直接发布、不覆盖共享对象，不把多个 Path 的导入转换为批量迁移。预检查错误保留错误清单；重复导入按稳定编码提示，不静默重复创建。具体模板格式和导入量上限 P4。

## 6. 信息架构与通用 UI

### 6.1 页面导航 D

| 页面编号 | 页面 | 入口 | 主任务 |
| --- | --- | --- | --- |
| P01 | 链路监控总览 | 链路监控默认入口 | 业务查询、拓扑聚焦和定位异常 |
| P02 | 业务链路管理 | 管理入口 | 查询 Path、创建、编辑、单条启停 |
| P03 | 业务链路编排 | 新建/编辑 | 草稿配置与校验发布 |
| P04 | 业务链路详情 | 列表/总览 | 查看当前发布拓扑及历史 |
| P05 | 拓扑资源 | 管理入口，Node/Edge 页签 | 资源查询、复用和引用治理 |
| P06 | 导入配置 | 链路管理导入按钮 | 模板初始化及草稿校验 |

操作日志和字典维护优先使用现有平台页面并携带对象筛选条件；没有可复用页面时提供本模块最小入口，不建设新权限系统。Span 不增加一级菜单。

### 6.2 布局规范 D

沿用现有 B 端平台导航、字体、表格、弹窗和按钮样式。建议以 1440px 桌面宽度设计，主内容内边距 24px、区块间距 16px，正文 14px；具体值由现有设计系统覆盖。

表格页：标题及动作 → 查询区 → 结果数量 → 表格 → 分页。编辑页：顶栏 → 左资源面板 → 中央画布 → 右属性面板 → 底部校验结果。普通确认用居中弹窗，复杂编辑用完整页面；右属性面板固定占位，避免覆盖画布。

正常用绿色及文字，异常用红色及图标，未知用灰色及问号；部分异常/部分未知采用对应颜色加明确文字。选中对象用蓝色描边或外层光晕，保留运行状态标识，避免蓝色替换状态色。方向箭头清晰，实线/虚线不承担运行执行顺序含义。

### 6.3 通用 UE D

- 查询按钮提交筛选，重置恢复默认；返回列表保留筛选和页码。
- 必填项就近提示；发布失败定位到字段或画布对象；Toast 只提示结果，不承载唯一错误说明。
- 保存/发布提交期间按钮禁用并显示进度，重复点击不产生重复对象。
- 空列表、无匹配、无权限、请求失败、无状态数据分别呈现，不共用“暂无数据”。
- 弹窗聚焦首个输入或主要内容，关闭后焦点返回触发位置；键盘可访问操作，状态不只依赖颜色。
- 权限不足隐藏无权动作或依现有规范禁用；服务端仍校验，不依赖前端遮挡。

## 7. 页面 UI 与 UE 详细说明

### P01 链路监控总览

UI 结构 D：顶部“单位”省—地市二级级联复选、业务对象、Path 名称/标识、链路类型查询；删除 P01 的业务范围查询。中央采用上方网级、下方所选边缘单位的两层分区拓扑；Path 列表和对象详情可折叠，优先保证拓扑宽度。提供刷新、适应画布、缩放、清除聚焦及最近读取时间。

默认展示所选单位权限范围内已发布且启用 Path；单位初始值为原型样例设定，不构成正式默认政策。B：省级复选只选省级边缘节点，不自动选择地市；地市需另选，展开省列表不改变选择。多选单位共享同一网级层。D：单位面板提供搜索、已选数量、清空及显式勾选；多单位采用可滚动分栏/分批展示并始终列出全部已选单位。分批只是视图，不改变单条 Path 聚合范围。

B：网级及每个边缘单位均按一至四区组织。跨区和跨层 Edge 均经相应防火墙/隔离装置。下行四区为网级四区→跨层装置→边缘四区；下行其他区为网级四区→区间装置→网级三区→跨层装置→边缘三区→相应区间装置→边缘二区/一区。上行为边缘起点→相应装置→本单位三区→跨层装置→网级三区→区间装置→网级四区。仅保留真实连接的业务节点，附件孤立图形不作为有效拓扑。D：方向通过箭头、业务标签和链路聚焦表达；装置作为可选择的逻辑设备 Node，具体名称/类型仅为样例，不推定正式部署。

| 用户动作 | 系统反馈 |
| --- | --- |
| 按业务对象查询 | 列出该对象已启用的上/下行 Path，各自显示状态；无整体状态卡片 |
| 选择 Path | 高亮其完整 Node/Edge；不重排整图，保持用户位置 |
| 选择业务对象聚焦 | 高亮实际相关 Path，列出方向和独立状态；停用方向显示文字说明和详情入口，不伪装成实时图层 |
| 选择 Node | 详情显示资源身份、基础状态、最后更新时间；Role 按 Path 分组 |
| 选择 Edge | 详情显示两端、方向、业务作用、影响范围、引用 Path 及状态 |
| 清除聚焦 | 恢复当前查询结果内全部拓扑和原视口 |
| 选择省级单位 | 仅呈现该省级边缘节点与网级之间的完整拓扑，不自动展示地市 |
| 另选一个或多个地市/省份 | 展示所有显式选择单位；网级公共Node复用，不画省份转发地市的隐含连接 |
| 多单位切换可见分批 | 保留已选清单、筛选和Path状态，提示当前可见单位及总数；属于D视图方案 |

同一对 Node 多 Edge 使用有间距的曲线和作用标签，反向 Edge 箭头方向相反。低缩放下可暂隐藏文字，点击或悬停可查看；不能合并成不可区分的单条业务关系。

Role 在单 Path 聚焦时显示该 Path 的多个 Role；多 Path 总览时显示“参与 N 条链路”，详情逐条展示 Role，避免把所有 Role 当全局角色。

D：区域分组作为视觉容器，不改变对象身份。画布刷新保留缩放、位置和选择；选择对象已不在结果中时清除选择并给出说明。页面离开停止刷新，后台失败时保留上次画面并标注刷新失败；数据有效期仍按真实状态时间判断。

空态文案：“暂无已启用的业务链路”，提供有权限的管理入口；筛选空态：“没有符合条件的业务链路”，提供重置。

### P02 业务链路管理

查询字段：业务对象、Path 名称/标识、链路类型、业务方向、业务范围、配置状态、启停状态、运行状态。

表格列：名称、业务对象、类型、方向、范围、发布状态、是否有草稿、启停状态、运行状态/最后状态、更新时间、操作。未发布显示“— 未发布”，不显示正常或未知；停用行显示“已停用；最后状态 XX，时间 XX”。

顶部动作：新建、导入。每行动作：详情、编辑/继续编辑、启用或停用。无业务对象整体按钮、无批量迁移。D：Path 本体删除未在基线明确，本稿不提供该动作。

点击新建进入 P03；编辑已发布对象自动从当前生效配置起草，有既有草稿则进入该草稿。首次发布后返回详情；从详情返回列表保留原查询。

### P03 业务链路编排

顶栏显示 Path 名称、草稿标识、关联当前发布时间及保存时间；动作依次为返回、保存草稿、校验、发布。发布打开居中摘要弹窗，确认后生效，无审核任务。

左侧 Node 资源列表按名称、类型、范围查询，支持选择加入及新建。中间画布支持拖动位置、有向连线、对象选中和适应画布。右属性面板按选择显示以下内容：

| 选择项 | 属性面板 |
| --- | --- |
| 画布空白 | Path 基本信息、业务目标、方向、范围、归组信息 |
| Node | 资源信息只读摘要、当前 Path Role 多选、查看全局资源、从本 Path 移除 |
| Edge | 已引用资源只读语义字段、查看详情、替换关系、从本 Path 移除 |
| 新建 Edge | 源/目标、方向预览、作用/范围字典、复用候选列表 |

复用候选居中弹窗逐项展示五项匹配依据。选择复用带入 Edge 标识；选择独立创建生成新标识。重复添加同一 Node 定位原节点并提示“该节点已在链路中，可继续维护角色”。

替换 Node 后必须检查所有相邻 Edge，不自动篡改共享 Edge。Role 可作为待确认值带入，但维护人员检查后提交。不同 Path 内布局 D：各自保存草稿布局，统一总览采用独立自动布局，不反向改变其他 Path 的视图。

校验结果固定在底部，以“阻止发布”和“提醒”分组。点击错误高亮对应对象。边端点缺失、孤立节点及断开子图均阻止发布，列出节点和不连通分组；仍可保存草稿，不提供确认后放行按钮。连通性忽略边方向检查，不要求任意两点有向可达；分支、汇聚和反向交互本身不是错误。原停用资源引用保留列为待迁移提醒，新增停用引用列为阻止发布。

### P04 业务链路详情

顶栏：名称、业务对象、方向、范围、发布状态、启停状态、运行状态，编辑及单条启停按钮。中部页签“当前拓扑”“历史状态”“指标趋势”；若有草稿显示“存在未发布修改”，监控仍采用已发布配置。

当前拓扑沿用 P01 对象交互；旁侧按异常、未知分类列出原因对象，点击定位；全部正常时显示各状态数量，无业务对象总状态。

历史页包含范围选择、固定说明、Path 时间轴、当前拓扑和对象区间列表。默认 D：近 24 小时，可选近 1 小时、近 7 天、近 30 天及自定义有效范围。未来时间及窗口外时间不可选；跨窗口输入提示调整范围。

点击时间轴某一时刻：显示该时刻已存 Path 状态，当前拓扑对象按可得历史着色。对象区间列表列开始、结束、状态、区间内持续时间、来源。停用间隔、对象无历史和明确未知分别显示。

#### P04-3 指标趋势

链路详情新增“指标趋势”页签。入口包括 Path 摘要、Path 详情、Node 详情和 Edge 详情；从 Node/Edge 进入时必须携带当前 Path、方向及对象。返回总览恢复进入前的单位、业务对象、Path 聚焦和画布位置。

顶部固定整链时延卡片和趋势图，整链时延来自起点到终点的独立端到端探测，不由 Edge 分段相加。下方使用单对象选择器，一次只查看一个 Node 或 Edge：Edge 显示该 Path 方向上的分段时延与丢包率；普通业务服务显示逻辑节点或具体 IP 的时延、丢包率；隔离装置显示正向/反向吞吐量与丢包率；防火墙显示入向/出向吞吐量和当前总连接数。

时间范围默认近 1 小时，提供近 6 小时、24 小时、7 天、30 天及不超过 30×24 小时的自定义范围。全部图使用同一时间范围、自动聚合粒度和联动游标，并显示实际粒度。不同量纲必须拆图，不使用双轴；同一指标的方向/IP可在同图切换或对比。

统计序列：时延默认平均值、P95并可切换最大值；吞吐量默认平均值并可切换最大值；丢包率默认平均值、最大值；连接数默认平均值并可切换最大值。图例控制显隐，悬停展示同一时点各可见序列。时间桶状态按异常、未知、正常的严重度取值并通过背景或点色表达。

缺失值必须断线，不补零、不沿用前值。空态分别使用“该对象不适用此指标”“采集失败，当前区间无可用数据”“所选时间超出30天保留期”。指标状态来自监控数据；过期指标显示未知且不展示旧值。页面不展示指标来源及采集时间，也不把原型数值解释为正式阈值。

#### P01 当前指标增量

Path 列表增加最近一次有效整链时延和指标状态；单 Path 聚焦时在画布标题区突出。Node 卡片不铺开指标，仅在指标异常时显示角标。Node 详情按普通服务、隔离装置、防火墙分别显示确认字段；Edge 详情显示当前 Path 方向的分段时延和丢包率。多 Path 或多单位不计算合并时延。

### P05 拓扑资源

Node 与 Edge 双页签，提供查询、查看详情、新建、受控修改展示属性、停用、满足条件时删除。Node 列表：名称、类型、稳定标识、范围、资源启用状态、运行状态、引用数。Edge 列表：名称、源→目标、作用、影响范围、资源启用状态、运行状态、引用数。

资源详情展示基础信息、状态与历史入口、已发布引用/草稿引用、操作记录。引用列表可跳转具体 Path 编辑；没有从资产侧直接解除引用或批量迁移操作。

语义字段在已发布资源详情只读，提供“创建替代资源”，进入新资源表单；新资源创建本身不替换任何 Path。停用弹窗列出受影响引用及“已有引用保留，后续请逐条调整”。删除不可执行时直接说明条件，如“已被 2 条已发布链路、1 份草稿引用”。

### P06 导入配置

步骤区：上传模板 → 校验与人工确认 → 创建草稿结果。错误表显示表名、行号、业务编码、字段、原因和修正提示。Node/Edge 候选必须人工确认，不能仅按名称关联。成功结果列草稿及进入编辑入口，无“全部发布”或“迁移全部”按钮。

## 8. 校验与错误处理 D

| 编号 | 触发条件 | 处理 |
| --- | --- | --- |
| V01 | 必填业务字段缺失 | 草稿可保存，发布前阻止并定位 |
| V02 | 空拓扑或 Edge 引用端点缺失 | 阻止发布；保留草稿 |
| V03 | 同 Path 重复 Node/Edge 引用 | 去重引用，定位已有对象；Role 汇总 |
| V04 | 同业务对象同方向已有 Path | 阻止归组发布，列出冲突 Path |
| V05 | Role 违反字典必选/互斥 | 阻止发布，指出具体冲突项 |
| V06 | 新引用已停用或已删除资源 | 阻止发布，提示选择有效资源 |
| V07 | 五项 Edge 属性不同却请求复用 | 阻止错误复用，提示选择或新建正确关系 |
| V08 | 已发布资源语义原地修改 | 引导创建替代资源，不写入共享对象 |
| V09 | 生效配置已被他人更新 | 保留本地草稿，提示刷新并重新校验 |
| V10 | 发布请求超时/返回不明 | 查询真实生效配置，避免盲目重复提交 |
| V11 | 孤立 Node 或断开子图 | 阻止发布、定位问题；可保存草稿，无人工放行。按忽略方向后的连通性检查，不禁止合法分支、汇聚、反向交互 |
| V12 | 无有效状态数据 | 未知并解释原因，不阻止静态配置发布 |
| V13 | 导入部分行不合法 | 预校验不写入发布配置；修正后再创建草稿 |

## 9. 权限 操作日志与接入

复用现有账户、组织范围及操作权限。D：仅映射查看、编辑、发布、启停、资源维护、字典维护和导入动作到既有权限项，不新定义用户角色。无权限的资源不能通过查询、引用列表或导出错误信息泄露详情。

操作日志记录对象类型/标识、动作、操作者、时间、结果、配置变更摘要及关联 Path。归组、Role、资源属性、引用、启停、发布、停用/删除和导入均记录。查询浏览不额外设计新的审计策略。

外部探针输入可形成 Node/Edge 状态，不要求其伪装为 Span。真实 Span 字段用于必要关联；未匹配和冲突在既有接入结果或对象状态原因中查看，必要时提供最小列表，不建设独立复杂治理平台。真实 Span 样本尚未验证，不宣称已实现端到端关联。

| A27 | 外部探针没有 Span 父子字段 | 可提供对象状态，不伪造实际执行关系 |

| A29 | 无发布权限或跨组织不可见 | 沿用既有体系拒绝操作/访问，无新增审批角色 |
| A30 | 模板导入并人工校验 | 只生成草稿，发布需逐条确认；无批量迁移 |

验收表中涉及 D 细节的条目需随本稿评审确认；B 对应基线为固定约束。性能验收不能以未知规模给出虚构响应时限。

### 12.1 实现方案补充 D

- 单 Path 发布：在一次一致性提交中校验生效配置、归组方向唯一性、引用资源及权限，写入配置、关系和发布结果。失败保留原配置；使用同一操作标识查询或重试可返回原结果，避免重复生效。状态聚合读取同一生效配置快照，异步重算时显示正在更新，不拼接新旧组成。
- 新建资源：P03/P05 保存资源后产生可引用的资源记录，但只有已发布 Path 的引用才进入统一监控拓扑。未发布资源如已被其他草稿引用，不可静默修改身份或删除；创建替代资源不自动获取旧对象状态。资源首次被 Path 发布引用时记录曾发布事实，用于删除校验；不新增独立资源审批。
- 归组入口：P03 业务信息提供选择/填写业务对象编码、名称、目标和范围。无对应方向时可提交单方向归组草稿；存在对象时使用其业务属性匹配，发布时再次校验唯一性，避免两份草稿并发占用同一方向。公共业务对象属性变更不在本稿新增全局编辑入口。
- 导入提交：D 方案采用单次上传预校验全部通过、人工确认后一次创建本批草稿及新资源；失败不留下部分新记录，原有资源不覆盖。请求重复使用同一导入操作标识返回同批结果。若实际规模不支持该方式，需先调整 D 方案和验收，不静默改为部分成功。
- 自动过期：有效期检查由后端在无人打开页面时仍执行，触发未知和相关启用 Path 重算；前端刷新只读取结果。处理乱序、重复和多个来源所需的时间及来源契约仍依赖 P3。

### 12.2 补充验收场景 D

| 编号 | 前置与操作 | 预期 |
| --- | --- | --- |
| A31 | 同方向两份草稿并发发布同一业务对象 | 最多一个占用成功；另一份保留草稿并返回冲突，不部分写入 |
| A32 | 一个 Path 发布时模拟提交失败，再用同一操作标识重试 | 配置及引用无半成品，最多生效一次，结果可查询 |
| A33 | 在编辑页创建 Node 并仅保存草稿 | 资源可辨认但不进入默认拓扑；其他草稿引用后不能被原编辑者静默改身份 |
| A34 | 无人访问页面时超过状态有效期 | 后端产生未知及相应 Path 结果，打开页面可见已发生的变化 |
| A35 | 导入预校验通过后在写入中途失败并重试 | 本批无部分草稿/资源残留；已有配置不变，成功重试不重复创建 |
| A36 | 当前 Node 有过去状态但当时是否属于 Path 不可知 | 只展示对象自身历史和固定解释提示，不断言历史参与关系 |
| A37 | 两人打开同一草稿，第一人保存后第二人提交旧修订号 | 第一人内容保留，第二人收到冲突并保留未提交内容；发布同时校验草稿修订及生效配置 |
| A38 | 无既有业务对象/无反向候选，输入首条方向的编码、目标、范围并发布 | 可以建立单方向归组；同编码属性冲突则明确失败且保留草稿 |
| A39 | 已发布 Path 保留原停用引用，仅修改名称或 Role，其他校验通过 | 允许发布，保留待迁移提醒；草稿内移除再加回同一引用按最终集合判定 |
| A40 | 首次发布引用停用资源，或生效版本已解除后再次添加 | 均作为新增引用阻止发布，保留草稿和原生效配置 |
| A41 | 草稿含孤立节点（包括仅单个无边节点） | 可保存，发布被阻止并定位；无确认放行入口 |
| A42 | 草稿由两个各自有边但彼此断开的子图组成 | 发布被阻止并列出不连通分组；连接后重新校验通过才可发布 |
| A43 | 拓扑忽略方向后连通，包含分支、汇聚或反向交互，其他校验通过 | 不因未有向全连通或存在反向交互而阻止发布 |

A18–A20 的状态测试准备固定三对象组成：全正常、全异常、全未知、正常/异常/未知混合、正常/未知两类组合；对照公式逐项断言。A21/A34 使用接入已确定的有效期 T，在最后有效时间加 T 前、等于及超过边界分别验证。A39–A43 对应已确认的两项发布规则。
