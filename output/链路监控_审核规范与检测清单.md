# 链路监控审核规范与检测清单

版本 R1，2026-09-15。用于需求、PRD、原型、页面实现和测试交付的持续质量审核。

## 审核角色

设独立交付物审核角色：读取当前基线、待审产物和变更记录，先按清单逐项检查，报告证据和问题；作者修订后由审核者复核。审核者不得自行扩大业务范围或修改冻结基线。本角色是项目协作中的质量责任，不在产品中增加发布审批或新权限角色。

每次交付及重大修改执行一次；上下文切换后从交接文件继续，沿用清单编号。增加检测项使用新编号，不重排已有编号。

## 执行规则

1. 固定基线版本及待审文件版本/哈希；读取完整材料。
2. 对下表每项记录结果、证据定位和问题编号。结果只能为通过、未通过、待验证、不适用；不适用说明理由。
3. B 为已确认规则，D 为设计提案，P 为缺失实施输入。D 标签不能为超范围功能或无依据的业务限制免责；业务政策推断必须移出正式执行规则或请求业务裁定。普通控件/布局可作为设计细化。
4. 问题分级：S1 基线冲突/错误状态/数据破坏；S2 主流程缺口/无法实现或测试；S3 文案、定位和一致性问题。记录修订及复核证据，不能只写“已修复”。
5. 无未关闭 S1/S2 才能通过当前阶段；外部证据缺失可对可推进阶段通过，但明确阻止的后续阶段。文档审查不等于接口、性能和运行验证。

## 检测项

| 编号 | 检测内容 | 方法与通过标准 |
| --- | --- | --- |
| C01 | 基线版本及依据 | 与唯一基线逐节映射，无旧决策覆盖新决策 |
| C02 | 一期功能范围 | 所有页面、按钮、流程、验收均在范围内；排除项无变相引入 |
| C03 | 事实与提案 | 用户结论、设计细化、未知参数明确；无虚构业务/接口/指标 |
| C04 | 模型关系及唯一性 | Node/Edge/Path/Role/Span 分工、引用基数、去重一致 |
| C05 | 业务归组 | 条件、方向唯一、单方向、未归组及冲突处理完整 |
| C06 | 草稿与发布 | 保存、生效、失败、并发一致；不无感覆盖发布配置 |
| C07 | 共享资源生命周期 | 创建、受控修改、替换、移除、停用、删除及引用影响闭合 |
| C08 | 状态计算 | 五种聚合互斥且完备，空集、过期、停用、重启边界正确 |
| C09 | 历史与时间 | 区间窗口、无记录、停用空档及当前拓扑展示不矛盾 |
| C10 | 主流程完整 | 入口、前置条件、输入、结果、失败恢复和返回路径可执行 |
| C11 | UI 信息完整 | 每页字段、控件、数据来源、动作可映射到模型和规则 |
| C12 | UE 与异常态 | 保存保护、加载/失败/空态、错误定位、重复提交及可访问性 |
| C13 | 权限和审计 | 复用既有权限，未越权泄露；变更可追溯，无新增审批角色 |
| C14 | 外部状态与 Span | 外部探针与真实执行区分；未匹配处理及接入边界清楚 |
| C15 | 导入落地 | 模板关联、预校验、写入边界、失败及重复导入可执行 |
| C16 | 研发可实现性 | 实现机制可解释；关键原子性、并发和唯一性有方案，无循环依赖 |
| C17 | 测试可执行性 | 基线→规则→页面→用例可追溯；有前置、操作、可观测结果及反例 |
| C18 | 规模与外部依赖 | 字典/字段/时效/规模/性能等未证实内容列出负责人职能及关闭阶段 |
| C19 | 原型及实现一致性 | 原型与 PRD 操作/状态一致；实现需真实交互和接口结果证据 |
| C20 | 产物与交接 | 版本、链接、修订、审核范围、遗留事项及继续入口完整 |
| C21 | 原型规范范围门禁 | 仅形成规范和后续设计输入；不把本阶段文本审查表述为已完成原型、实现或联调 |
| C22 | 原型信息架构 | P01–P06 入口、返回路径、页面职责和跨页状态连续性完整，无新增越界一级能力 |
| C23 | 字段与控件标准 | 各页展示字段、输入控件、只读/可编辑边界、动作权限和数据来源可逐项定位 |
| C24 | 拓扑表达一致性 | Node/Edge/Path/Role 去重、方向、多 Edge、聚焦、选择、区域容器和布局持久化不改变业务语义 |
| C25 | 状态与历史表达 | 三态/五态、过期、停用、空档、无记录、当前拓扑历史局限及时区表达无混淆 |

## 各阶段证据要求

PRD：条款审查、场景推演、规则计算和可测试性。原型规范：页面职责、字段/控件、交互状态、全量追溯和后续交付门禁；仍不等于已有原型。原型：逐页画面、交互路径、空态/异常态。实现：真实交互、接口/权限/并发测试。上线前：真实数据规模、性能与状态数据质量。不得用前一阶段证据替代后一阶段。
